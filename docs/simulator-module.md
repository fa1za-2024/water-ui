This module allows developers to test the IoT pipeline (Node-RED -> InfluxDB -> Express -> React) via a UI. The Express backend handles the MQTT publishing. ## 1. Module Overview

**Purpose:** To allow developers to test the Water UI IoT pipeline directly from the dashboard UI without needing physical hardware or terminal access to a standalone simulator script.

**Architecture Flow:**
1. Developer enters MQTT and simulation parameters in the React UI.
2. React sends a POST request to the Express backend.
3. Express connects to the MQTT broker using the `mqtt` npm package.
4. Express generates randomized payloads based on the selected condition and publishes them to the broker at the specified interval.

**Topic Generation Rule:** The MQTT topic is NOT manually typed. It is auto-generated by the backend using the formula:
```text
sensors/<boardID>/data
```

## 3. Backend Logic (Express.js + MQTT)
### 3.1 MQTT Connection Strategy
The Express backend maintains a singleton MQTT client. When a simulation starts, it stores the setInterval ID in memory to allow stopping it later. Only one simulation can run at a time.

### 3.2 Data Generation Logic (Randomized by Condition)
To properly test the Node-RED thresholds, the generator MUST produce values that fall strictly within the following bounds:

Target Condition	pH Range	Turbidity Range (NTU)
Safe	7.0 - 8.0	0.0 - 3.0
Acceptable	6.5 - 6.99 OR 8.01 - 8.5	0.0 - 5.0
Unsafe	< 6.5 OR > 8.5	5.1 - 1000.0 (High Turbidity) OR any value if pH is extreme
Other fields (batt_voltage, rssi, ts) are randomized every time regardless of condition:

batt_voltage: 3.0 - 4.2 V

rssi: -30 to -100 dBm

ts: Date.now() (Unix timestamp in milliseconds)

### 3.3 API Endpoints
POST /api/simulator/start
Body:
```json
{
  "brokerUrl": "mqtt://localhost",
  "port": 1883,
  "boardID": "AA240238",
  "sleepTime": 5000,
  "condition": "Unsafe"
}
```

Response (200 OK):
```json
{ "message": "Simulation started", "topic": "sensors/AA240238/data", "condition": "Unsafe" }
```
POST /api/simulator/stop
Body: None

Response (200 OK): 
```json
{ "message": "Simulation stopped" }
```

##  4. Implementation Code
### 4.1 Express Backend (backend/src/controllers/simulatorController.js)
```javascript
const mqtt = require('mqtt');

let simulationInterval = null;
let mqttClient = null;

// Helper: Random number in range
const randomInRange = (min, max) => parseFloat((Math.random() * (max - min) + min).toFixed(2));

// Helper: Generate payload based on condition
const generatePayload = (boardID, condition) => {
  let pH, turbidity;

  if (condition === 'Safe') {
    pH = randomInRange(7.0, 8.0);
    turbidity = randomInRange(0.0, 3.0);
  } else if (condition === 'Acceptable') {
    pH = Math.random() > 0.5 ? randomInRange(6.5, 6.99) : randomInRange(8.01, 8.5);
    turbidity = randomInRange(0.0, 5.0);
  } else { // Unsafe
    const type = Math.random();
    if (type < 0.5) {
      // Extreme pH
      pH = Math.random() > 0.5 ? randomInRange(0.0, 6.49) : randomInRange(8.51, 14.0);
      turbidity = randomInRange(0.0, 5.0);
    } else {
      // High Turbidity
      pH = randomInRange(7.0, 8.0);
      turbidity = randomInRange(5.1, 1000.0);
    }
  }

  return {
    boardID: boardID,
    pH: pH,
    turbidity: turbidity,
    batt_voltage: randomInRange(3.0, 4.2),
    rssi: Math.floor(-30 - Math.random() * 70),
    ts: Date.now()
  };
};

exports.startSimulation = (req, res) => {
  const { brokerUrl, port, boardID, sleepTime, condition } = req.body;

  if (simulationInterval) {
    return res.status(400).json({ error: 'Simulation is already running. Stop it first.' });
  }

  if (!boardID) {
    return res.status(400).json({ error: 'Board ID is required.' });
  }

  // Auto-generate topic from boardID
  const topic = `sensors/${boardID}/data`;
  const fullBrokerUrl = `${brokerUrl}:${port}`;

  mqttClient = mqtt.connect(fullBrokerUrl);

  mqttClient.on('connect', () => {
    console.log(`[Simulator] Connected to ${fullBrokerUrl}`);
    console.log(`[Simulator] Publishing to topic: ${topic} | Condition: ${condition}`);

    simulationInterval = setInterval(() => {
      const payload = generatePayload(boardID, condition);
      mqttClient.publish(topic, JSON.stringify(payload));
      console.log(`[Simulator Published to ${topic}]`, payload);
    }, sleepTime);

    res.status(200).json({ message: 'Simulation started', topic, condition });
  });

  mqttClient.on('error', (err) => {
    console.error('[Simulator] MQTT Error:', err.message);
    if (simulationInterval) {
      clearInterval(simulationInterval);
      simulationInterval = null;
    }
    if (!res.headersSent) {
      res.status(500).json({ error: 'Failed to connect to MQTT broker.' });
    }
  });
};

exports.stopSimulation = (req, res) => {
  if (simulationInterval) {
    clearInterval(simulationInterval);
    simulationInterval = null;
  }
  if (mqttClient) {
    mqttClient.end();
    mqttClient = null;
  }
  res.status(200).json({ message: 'Simulation stopped' });
};
```

```jsx
import React, { useState } from 'react';

  const [config, setConfig] = useState({
    brokerUrl: 'mqtt://localhost',
    port: 1883,
    boardID: 'AA240238',
    sleepTime: 5000,
    condition: 'Safe'

          </div>

            <label className="block text-sm font-medium text-gray-700">Board ID</label>
```

### 4.4 Standalone terminal simulator - **IMPLEMENTED** (T-334)

The UI module above needs the API, the frontend and a signed-in session. For a terminal check, a demo or a
scripted test there is now a separate script that publishes the **same** messages directly:

```bash
cd iot/simulator
npm install                                   # once - the only dependency is `mqtt`

node simulate-esp32.js                        # Safe, every 5000ms, until Ctrl+C
node simulate-esp32.js --condition Unsafe --interval 1000
node simulate-esp32.js --board PAGOH1 --count 5 --interval 500
node simulate-esp32.js --dry-run --count 3     # print payloads, publish nothing
```

Options: `--broker` (default `mqtt://localhost`), `--port` (1883), `--board` (AA240238), `--condition`
(Safe | Acceptable | Unsafe), `--interval` (5000 ms), `--count` (0 = until Ctrl+C), `--dry-run`, `--quiet`,
`--help`.

It is bound by the same rules as the module:

* the topic is **generated** from the board id - never typed - and an invalid id is refused before connecting
  (the API's own `^[A-Za-z0-9_-]{1,50}$` rule);
* the payload is the device's: `boardID`, `pH`, `turbidity`, `batt_voltage`, `rssi`, `ts` - exactly what
  `iot/esp32c3/water_quality_mqtt.ino` sends, with `ts` in epoch **milliseconds**;
* the three derived fields (`wq_status`, `batt_level`, `wifi_status`) are **not** sent - Node-RED computes them
  from the raw values (MASTER_CONTEXT.md 5.3), so sending them would impersonate the server;
* values follow 3.2, so a reading generated for a condition is classified as that condition by the flow;
* the status topic `sensors/<boardID>/status` gets a retained `online` on connect and `offline` on exit or crash,
  mirroring the firmware's Last Will.

> **Verified (T-334):** 42/42 against a live broker - the payload, the bounds, the derived classification for all
> three conditions, the retained status pair, and the failure paths (bad board id / unknown condition / unknown
> flag -> exit 2, unreachable broker -> exit 1 with a hint). There is no scaffolding to swap out later: the module
> in 4.1 can reuse this generator's bounds.

## 5. Critical Rules for AI
Backend MQTT: Never attempt to connect to MQTT directly from the React frontend using mqtt://. Always route through the Express backend.

Topic Auto-Generation: The backend MUST build the topic as `sensors/${boardID}/data`. Do not accept a manually entered topic from the frontend to prevent typos.

Condition Logic: The generatePayload function must strictly adhere to the bounds defined in Section 3.2 to properly test the Node-RED thresholds.

Singleton Pattern: Ensure only one simulation can run at a time. The startSimulation endpoint must return a 400 Bad Request if simulationInterval is already active.

Graceful Shutdown: The stopSimulation endpoint must clear the setInterval and close the MQTT client connection to prevent memory leaks.

Board ID Validation: The "Start Simulation" button must be disabled if the Board ID input is empty.
