# Water UI - Task Tracker

Step-by-step task list for the Water UI project. Tracks what is done, what is
next, and what is blocked.

- **Source of truth:** [`MASTER_CONTEXT.md`](MASTER_CONTEXT.md). Every task below
  cites the section or Rule it comes from. If this file and `MASTER_CONTEXT.md`
  disagree, `MASTER_CONTEXT.md` wins.
- **Structure:** [`project-structure.md`](project-structure.md)
- **Open decisions:** Appendix A of `MASTER_CONTEXT.md` (A1-A26) - see
  [Decisions required](#decisions-required) below.

## How to use this file

**Rule 8 of `MASTER_CONTEXT.md` makes this file mandatory:** refer to it before starting any task, mark tasks `[x]` when they are done, and add a task here whenever new work is required - *before* doing that work.

| Marker | Meaning |
| :--- | :--- |
| `[x]` | Done and verified |
| `[ ]` | Not started |
| `[~]` | Partially done / stubbed |
| `BLOCKED` | Waiting on a decision or an external step |

Task IDs are stable (`T-201`) so they can be referenced from commits, issues and
the docs. **When a task changes the system, update `MASTER_CONTEXT.md` in the same
change** - that is the sync rule in section 3 of that document.

Two conventions that keep this list honest:

1. **Evidence on completion.** A finished task records what proves it - the command
   run, the response observed, the artifact produced. "Done" without evidence is
   not done.
2. **New work becomes a task first.** Bugs, follow-ups and decisions that imply
   work are added as a new `T-xxx` (next free number in the phase) before the work
   happens, never recorded as an afterthought.

| A hop that fails silently must be verified by its effect | `BACKEND_URL=http://backend:5000` looked right and was unroutable, and the pipeline said nothing: the `http request` nodes have `senderr=false` and the flow's debug nodes have `console=false`, so neither `docker logs water_ui_nodered` nor a headless debug pane shows a failed POST. T-333 only found it by watching the Socket.io event from outside. When a hop is silent, assert on what it *produces* (the pushed reading), never on its configuration - and remember an env change needs `docker compose up -d <service>`, since `docker compose ps` will happily show the stale value |
| Removing a widget is not just deleting its JSX | A panel drags three more things behind it: the **API file** it was the only consumer of (`historicalApi.js`), the **shared helpers** it used (`overallWaterStatus()`, `turbidityPresentation()`, the chart-range constants, the `bar` colour tokens) and the **RTK tag it invalidated** (`Historical`, which silently became a no-op). T-331 cleaned all three - grep the component's imports and the tag it invalidated before calling a removal done |
| The map is centred on Pagoh by request, and the registry can hold boards anywhere | The seeded board sits in Bangkok, so a correct Pagoh-centred view legitimately shows an empty map area until `All boards` / `Malaysia` is clicked. Do not "fix" that by auto-fitting on load - it would drop the requested centre (T-315). **T-337 moved the request:** the centre is now the first registered station, and the same warning applies to `fitBounds` - the view is centred deliberately, so do not auto-fit on load |
| `MapContainer`'s `center`/`zoom` are read **once**, at mount | A centre that arrives from a query (T-337's first-registered station) cannot be honoured by the prop alone, so it needs an effect. But key that effect on the coordinate **values**, not the array: every registry refetch produces a new array with identical numbers, and an identity-keyed effect would re-centre the map on top of whatever the operator was looking at. A re-centre-on-refetch is invisible in a test that never pans - it is only caught by panning first (T-337) |
| Leaflet sets no `alt`/`title` on a `divIcon` | The `alt` prop on `<Marker>` is dead code for these colour-coded pins, so they are not addressable by attribute for accessibility or for tests. Verify pin↔board identity **geometrically** (the Web-Mercator offset between two pins must match the offset between their coordinates) or by position, never by DOM order (T-337) |
